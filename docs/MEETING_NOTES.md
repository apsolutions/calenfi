# Личные заметки к встречам: как их читает и пишет агент

Заметка к встрече — это повестка, вопросы и то, что нужно подготовить. Её видит только владелец календаря. Заметка никогда не попадает в событие у провайдера (Google, Office 365, Яндекс, Exchange) и участникам не видна. В приложении она правится в редакторе встречи, в поле «Заметки», а в карточке встречи показана текстом с замком. Встречи с заметкой помечены значком в сетке.

Документ для агента, которому нужно заполнять или дополнять такие заметки: собрать повестку из переписки, дописать вопросы перед созвоном, отметить итоги.

## Где лежат заметки

На каждом устройстве — в локальной базе Calenfi, таблица `meeting_notes` (одна строка на заметку). Между устройствами их переносит синхронизация через Google Tasks: каждая заметка — задача в отдельном списке **«Calenfi · заметки к встречам»** Google-аккаунта, через который идёт синхронизация (первый по id Google-аккаунт с доступом к задачам). Google Tasks личные, участники встреч их не видят.

Calenfi синхронизирует заметки при запуске, через 3 секунды после правки, раз в 5 минут, при возврате в приложение и в фоновой задаче на Android. При конфликте побеждает более поздняя правка, слияния текста нет.

Значит, у агента два пути:

1. **Через CLI Calenfi** (`tools/calenfi` в дереве исходников, см. [AGENT_API.md](AGENT_API.md)) там, где Calenfi установлен. Это основной путь.
2. **Напрямую через Google Tasks API** — с любой машины, где есть токен Google с доступом к задачам. Calenfi на всех устройствах подхватит правку при ближайшей синхронизации.

## Путь 1: CLI

Все команды печатают JSON. Один запуск занимает 40–60 секунд (компиляция Dart).

```bash
CAL=tools/calenfi

# 1. Найти встречу и её id. В выводе agenda у каждой встречи есть поле
#    "note", если заметка уже есть.
$CAL agenda --from 2026-10-06T00:00:00 --to 2026-10-07T00:00:00

# 2. Прочитать заметку (команда сначала забирает правки с других устройств).
$CAL note --id 'acc-yandex:events-10922764:abc123'

# 3. Записать заметку целиком (после записи она сразу уходит в Google Tasks).
$CAL note --id 'acc-yandex:events-10922764:abc123' --set 'Повестка:
1. Статус интеграции
2. Сроки пилота
Подготовить: цифры по нагрузке'

# 4. Удалить заметку.
$CAL note --id 'acc-yandex:events-10922764:abc123' --clear

# 5. Просто синхронизировать заметки.
$CAL notes-sync
```

Ответ `note`:

```json
{"ok": true, "syncedVia": "me@example.com", "id": "acc-yandex:…", "title": "Созвон", "note": "Повестка: …"}
```

`syncedVia` есть только после записи или удаления: через какой аккаунт заметка ушла в Google Tasks. Нет поля — синхронизации на этом устройстве нет, заметка осталась локальной.

**Дописать, а не заменить.** `--set` заменяет весь текст. Чтобы дополнить, сначала прочитать заметку, добавить свой текст к прочитанному и записать результат одной командой:

```bash
ID='acc-yandex:events-10922764:abc123'
old=$($CAL note --id "$ID" 2>/dev/null | python3 -c 'import sys,json; print(json.load(sys.stdin).get("note") or "")')
new="$old

Итоги (агент, $(date '+%d.%m %H:%M')): договорились о пилоте на ноябрь."
$CAL note --id "$ID" --set "$new"
```

Между чтением и записью владелец может поправить заметку на другом устройстве; более поздняя запись затрёт его правку. Читать и записывать подряд, без долгих пауз между ними.

**Какой id брать.** Любой id из вывода `agenda` (основная копия склейки) или из `sources`. Заметка общая для всех склеенных копий встречи: записанная под одним id, она находится по любому другому.

## Путь 2: Google Tasks API

Нужен OAuth-токен Google с областью `https://www.googleapis.com/auth/tasks` для аккаунта, через который идёт синхронизация. Calenfi держит такой токен в своём хранилище секретов: это токен Google-аккаунта, если при входе выдан доступ к задачам, или отдельный токен под ключом `token:gtasks_<EMAIL>` (адрес в верхнем регистре, всё кроме A–Z и 0–9 заменено на `_`). Токены в ответы, логи и коммиты не переписывать.

**Список.** `GET https://tasks.googleapis.com/tasks/v1/users/@me/lists`, взять список с названием ровно `Calenfi · заметки к встречам`. Нет списка — его создаст Calenfi при первой синхронизации; агенту создавать не нужно.

**Задача-заметка.**

- `title` — `Название встречи · ДД.ММ.ГГГГ ЧЧ:ММ` (местное время). Только для человека, Calenfi по заголовку встречу не ищет.
- `notes` — текст заметки, затем служебный хвост:

```
Повестка:
1. Статус интеграции

⸻
calenfi-note {"id":"e6d2f734-…","start":1790949600000,"keys":["id:acc-yandex:events-10922764:abc123","key:созвон по интеграции|1790949600000|1790953200000"]}
```

Хвост начинается с пустой строки, строки `⸻` и префикса `calenfi-note `, дальше одна строка JSON:

| Поле | Что это |
|---|---|
| `id` | id заметки в Calenfi. Для новой заметки — любой новый UUID. |
| `start` | начало встречи, миллисекунды Unix, UTC |
| `keys` | по каким ключам Calenfi узнаёт встречу |

Ключи бывают трёх видов, хватит любого одного:

- `id:<id события>` — id копии встречи из `agenda`, например `id:acc-o365:AAMk…`;
- `uid:<UID провайдера>|<начало, мс UTC>`;
- `key:<название>|<начало, мс UTC>|<конец, мс UTC>` — название в нижнем регистре, без пробелов по краям, повторные пробелы схлопнуты в один. Это единственный ключ, который агент может составить, не зная id события: название и время встречи видны в любом календаре.

**Правка существующей заметки.** Заменить текст до хвоста, хвост оставить как есть: `PATCH …/lists/{listId}/tasks/{taskId}` с полем `notes`. Calenfi сравнит время правки задачи (`updated`) со своей и возьмёт более позднюю.

**Новая заметка.** `POST …/lists/{listId}/tasks` с `title` и `notes` в формате выше. Calenfi на всех устройствах привяжет её к встрече по ключам при ближайшей синхронизации (не позже чем через 5 минут, пока приложение открыто).

**Удаление.** `DELETE …/lists/{listId}/tasks/{taskId}` — заметка пропадёт на всех устройствах.

Задачи без хвоста `calenfi-note` Calenfi не трогает: в список можно класть и обычные задачи, они не станут заметками.

## Правила для агента

- Писать только в заметки. Описание события (`description`) уходит участникам — туда повестку, вопросы и оценки людей не класть.
- Не писать в заметки пароли, токены и другие секреты: заметка лежит в Google Tasks открытым текстом.
- Дописывать, а не затирать: прочитать текущий текст и добавить свой блок с пометкой, что это написал агент, и временем.
- Новую заметку от имени агента начинать с заголовка блока, например `Повестка (агент, 06.10):`, чтобы владелец видел, что текст не его.
- Не менять служебный хвост у существующих задач, кроме случая, когда встреча перенесена и нужно добавить ключ нового времени.
- Проверить результат: `note --id` после записи должен вернуть записанный текст, а при пути через Tasks — задача с хвостом должна появиться в списке.

## Если заметка не синхронизируется

- В Calenfi: Настройки → «Заметки к встречам». «Только на этом устройстве» значит, что у Google-аккаунта нет доступа к задачам: его нужно один раз переподключить (Настройки → Учётные записи → аккаунт → «Переподключить»).
- Журнал: Настройки → Диагностика → «Журнал событий и ошибок», строки `[notes]`. Файл `calenfi.log` лежит в каталоге конфигурации: `~/.config/calenfi/` на Linux, `~/Library/Application Support/calenfi/` на macOS.
- Код: хранилище — `lib/data/repositories/notes_repository.dart`, синхронизация — `lib/data/notes/notes_sync.dart`, команды CLI — `_note` в `bin/calenfi.dart`.
